# Recruit demand coverage

This is an implementation review, not admission. The exact proposal has 17 input
members. `demand-surface-probe.json` pins inspected source files and five actual
probes using the disposable operational catalogue fixture. At the pinned revision,
all five demands passed HG ingress validation with the supplied instance context,
then failed public dispatch. Exact occurrence recruitment has since been implemented;
the historical probe is retained unchanged. The other four remain implementation gaps.

| Declared member | Current public path or remaining gap |
| --- | --- |
| query | Local, HTTP, verified witnesses and one configured Python callable pass. Interpreter currently supports connected ownership joins; arbitrary relationship queries are not implemented. |
| classification_group | HG-valid `kernel` probe rejected by exact-definition fallback. Catalogue filtering remains open. |
| authority_domain | HG-valid `system` probe rejected by exact-definition fallback. Catalogue filtering remains open. |
| definition | One exact definition and multiple explicit definitions are supported; combinations with other members need conformance evidence. |
| genus | One genus expansion is supported; repeated genus and combined demands are not implemented. |
| guarantee | No public dispatcher implementation; generic reference validation alone is insufficient. |
| relationship_binding | Supported inside the specialised traversal structure, not as the standalone declared member. |
| value | No standalone public query path. |
| value_type | Supported with one occurrence_subject in the property provider; standalone and combined cases remain open. |
| occurrence | Exact single/multiple identities now use the selected HG occurrence port, native ownership witnesses, local/HTTP verification and SWC evidence retention. Unknown or incompatible identities are refused; invisible owners yield no exposed occurrences. Combinations with other demand members remain open. |
| occurrence_type | No standalone public dispatcher path. |
| occurrence_subject | One subject plus a literal value_type is supported; repeated subjects and other combinations remain open. |
| relationship_traversal | One directional binding traversal is supported; repeated and combined traversals remain open. |
| scope_subject | HG-valid subject probe rejected. The fallback omits instance context and misleadingly reports HG rejection. |
| permitted_policy | No admitted operational Policy evaluator; do not implement a caller permission bypass. |
| denied_policy | Same admission/evaluation prerequisite; a caller filter does not establish authority. |
| instant | HG-valid timestamp probe rejected; temporal interpretation requires the intended HG-governed query semantics. |

The successful ownership-query work closes one integration gap. It does not close
this table, admit Recruit, or justify silently deleting its remaining members.
Field multiplicity and combination semantics must follow the reviewed operational
definition and HG meaning; do not infer them from Python list shape alone.

Next implementation order: catalogue classification/domain filtering with explicit combination semantics;
remaining query composition; Policy/time interpretation where their governing
meaning is available. Maintain the independent external-catalogue admission and
exact SWOS selection requirement. Existing selection/coverage/host-budget fields
in legacy providers are withdrawn framing and must not be restored as HG meaning.
